PART 1 OF 3

Model Architecture

The Transformer has no recurrence and no convolution — just attention, stacked six layers deep on each side. This part takes the architecture apart piece by piece, in the order the notebook builds it: framework first, math primitives second, full assembly last.

1.1The Big Picture

EncoderDecoder — the container everything plugs into

Before opening any individual class, it's worth seeing the shape of the whole pipeline once. The EncoderDecoder class is deliberately thin — it holds five sub-modules built elsewhere and just calls them in the right order.

Cell 4 — EncoderDecoder
# the top-level container: wires encoder, decoder, embeddings, generator together
class EncoderDecoder(nn.Module):
    def __init__(self, encoder, decoder, src_embed, tgt_embed, generator):
        self.encoder = encoder        # Encoder stack, N=6 layers
        self.decoder = decoder        # Decoder stack, N=6 layers
        self.src_embed = src_embed    # Embedding + PositionalEncoding (source)
        self.tgt_embed = tgt_embed    # Embedding + PositionalEncoding (target)
        self.generator = generator    # Linear(d_model, vocab) + log_softmax

    def forward(self, src, tgt, src_mask, tgt_mask):
        return self.decode(self.encode(src, src_mask), src_mask, tgt, tgt_mask)

    def encode(self, src, src_mask):
        return self.encoder(self.src_embed(src), src_mask)

    def decode(self, memory, src_mask, tgt, tgt_mask):
        return self.decoder(self.tgt_embed(tgt), memory, src_mask, tgt_mask)

Splitting encode() and decode() into separate methods — rather than one monolithic forward pass — is not incidental. The encoder needs to see the entire source sentence before it can produce a useful representation, but the decoder can only emit one token at a time. That asymmetry is exactly why the encoder's output is called memory: it's computed once, then reused across every decoding step.

Why this matters

encode() runs exactly once per source sentence. decode() runs once during training (teacher forcing sees the whole target at a time) but is called repeatedly, token by token, during inference. This "encode once, decode many" pattern shows up again in greedy decoding (3.3).

1.2The Generator

Turning a hidden vector into a word

The last step of the pipeline converts a 512-dimensional decoder output into a probability distribution over the vocabulary.

Cell 5 — Generator
class Generator(nn.Module):
    def __init__(self, d_model, vocab):
        self.proj = nn.Linear(d_model, vocab)   # (batch, seq, 512) -> (batch, seq, vocab)

    def forward(self, x):
        return log_softmax(self.proj(x), dim=-1)   # log-probabilities over the vocabulary
Math

The linear projection maps from the model's internal space (ℝ⁵¹²) into vocabulary space (ℝ|V|). log_softmax is used instead of plain softmax because log-probabilities are numerically more stable — and because nn.KLDivLoss, the criterion behind label smoothing (2.3), expects log-probabilities as input.

Notice that EncoderDecoder.forward() from 1.1 never calls the generator. It's applied separately — once per label position during loss computation, and once for just the newest position at each step of inference.

1.3The Encoder Stack

Six identical layers, deep-copied

The encoder stacks N=6 identical layers on top of one another, followed by a final normalization. The clones() helper is what makes "identical" mean identically shaped rather than literally the same object.

Cells 6–7 — clones() and Encoder
# deep-copy a module N times so each copy gets its own independent weights
def clones(module, N):
    return nn.ModuleList([copy.deepcopy(module) for _ in range(N)])

class Encoder(nn.Module):
    def __init__(self, layer, N):
        self.layers = clones(layer, N)      # 6 independent EncoderLayer instances
        self.norm = LayerNorm(layer.size)   # final normalization

    def forward(self, x, mask):
        for layer in self.layers:
            x = layer(x, mask)
        return self.norm(x)
Key insight

copy.deepcopy() is doing real work here. Reuse the same object six times without deep-copying and all six layers would literally share one set of weights — updating layer 1 during backprop would silently change layers 2 through 6 too, collapsing the stack into one layer applied repeatedly.

1.4LayerNorm & Residual Connections

The two patterns that make six layers trainable

LayerNorm normalizes each token's 512-dimensional feature vector independently — across features, not across the batch — which is what makes it suitable for variable-length sequences.

Cell 8 — LayerNorm
class LayerNorm(nn.Module):
    def __init__(self, features, eps=1e-6):
        self.a_2 = nn.Parameter(torch.ones(features))   # gamma: learnable scale
        self.b_2 = nn.Parameter(torch.zeros(features))  # beta: learnable shift

    def forward(self, x):
        mean = x.mean(-1, keepdim=True)
        std = x.std(-1, keepdim=True)
        return self.a_2 * (x - mean) / (std + self.eps) + self.b_2

SublayerConnection — residual + pre-norm

Every sublayer (attention or feed-forward) is wrapped in a residual connection. This implementation uses pre-norm — normalizing before the sublayer runs, not after — which trains more stably than the original paper's post-norm.

Cell 9 — SublayerConnection
class SublayerConnection(nn.Module):
    def __init__(self, size, dropout):
        self.norm = LayerNorm(size)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x, sublayer):
        return x + self.dropout(sublayer(self.norm(x)))   # residual connection
Math output = x + Dropout( Sublayer( LayerNorm(x) ) )
Why this matters

The residual connection is arguably the single most load-bearing pattern in the whole network. It lets gradients flow straight through, which is what makes a 6-layer stack trainable at all — each layer only has to learn a small correction to its input, not a full transformation from scratch.

1.5Encoder Layer & Decoder Layer

Two sublayers vs. three

An EncoderLayer wraps two sublayers — self-attention, then feed-forward. A DecoderLayer wraps three — masked self-attention, cross-attention to the encoder's memory, then feed-forward.

Cell 10 — EncoderLayer
class EncoderLayer(nn.Module):
    def __init__(self, size, self_attn, feed_forward, dropout):
        self.self_attn = self_attn
        self.feed_forward = feed_forward
        self.sublayer = clones(SublayerConnection(size, dropout), 2)

    def forward(self, x, mask):
        x = self.sublayer[0](x, lambda x: self.self_attn(x, x, x, mask))   # Q=K=V=x
        return self.sublayer[1](x, self.feed_forward)
Cell 12 — DecoderLayer
class DecoderLayer(nn.Module):
    def __init__(self, size, self_attn, src_attn, feed_forward, dropout):
        self.self_attn = self_attn      # masked self-attention
        self.src_attn = src_attn        # cross-attention to encoder memory
        self.feed_forward = feed_forward
        self.sublayer = clones(SublayerConnection(size, dropout), 3)

    def forward(self, x, memory, src_mask, tgt_mask):
        m = memory
        x = self.sublayer[0](x, lambda x: self.self_attn(x, x, x, tgt_mask))
        x = self.sublayer[1](x, lambda x: self.src_attn(x, m, m, src_mask))   # Q=decoder, K=V=encoder
        return self.sublayer[2](x, self.feed_forward)
Why the extra sublayer?

Cross-attention (src_attn) is the only point in the entire architecture where information crosses from the source language into the target language. The query comes from the decoder ("what am I looking for?"); the key and value come from the encoder's memory ("what's available to look at?"). Remove it, and the decoder could only ever see what it has already written.

1.6Attention Masking

subsequent_mask() — stopping the decoder from peeking ahead

During training, the decoder is shown the entire target sequence at once for speed (teacher forcing). Without a mask, position i could just copy the answer straight out of position i+1 — the causal mask exists to make that structurally impossible.

Cell 13 — subsequent_mask()
def subsequent_mask(size):
    attn_shape = (1, size, size)
    # upper-triangular: a 1 at [i, j] means "position j comes after position i"
    mask = torch.triu(torch.ones(attn_shape), diagonal=1).type(torch.bool)
    return mask == 0   # flip: True = allowed to attend, False = blocked
allowed to attend blocked

A 6-token sequence, last two positions padded. Rows are the position doing the attending; columns are the position being looked at.

Exposure bias — what breaks without it

A model trained with no future mask could drive its training loss to zero by simply copying the next input token, without learning anything about the actual task. At real inference time, future tokens don't exist yet — a model trained that way would be lost the moment it had to generate for real. The mask closes that shortcut during training so the model is never rewarded for cheating.

1.7The Attention Mechanism

Scaled dot-product attention, then splitting it into 8 heads

This is the core operation: for every query position, decide how much to listen to every key position, then blend the corresponding values accordingly.

Cell 15 — attention()
def attention(query, key, value, mask=None, dropout=None):
    d_k = query.size(-1)                                     # 64, dimension per head
    scores = torch.matmul(query, key.transpose(-2, -1)) / math.sqrt(d_k)
    if mask is not None:
        scores = scores.masked_fill(mask == 0, -1e9)         # push masked scores to ~0 after softmax
    p_attn = scores.softmax(dim=-1)
    if dropout is not None:
        p_attn = dropout(p_attn)
    return torch.matmul(p_attn, value), p_attn                # output, and the weights themselves
Math Attention(Q, K, V) = softmax( QKᵀ / √d_k ) · V

A tiny worked example with d_k = 2: say the query for "cats" is [1, 0], and the keys for "I", "love", "cats" are [1,1], [0,1], [2,0].

cats · I
0.29
cats · love
0.14
cats · cats
0.57

Raw dot products [1, 0, 2] → scaled by √2 → softmax → weights that sum to 1. The new "cats" vector becomes 29% of value(I) + 14% of value(love) + 57% of value(cats).

Why divide by √d_k?

If query and key entries are random with variance 1, their dot product over d_k dimensions has variance d_k. As d_k grows to 64, raw scores get large — which pushes softmax toward near-0/near-1 outputs almost everywhere, and its gradient collapses toward zero right along with it. Dividing by √64 = 8 keeps the score variance roughly at 1, where softmax still has a useful gradient to learn from.

Multi-Head Attention — 8 heads, one reshape trick

Rather than one attention computation over the full 512 dimensions, the model splits Q, K, and V into h=8 heads of d_k=64 each, runs the exact same attention() function on every head in parallel, then concatenates the results back together.

Cell 16 — MultiHeadedAttention
class MultiHeadedAttention(nn.Module):
    def __init__(self, h, d_model, dropout=0.1):
        self.d_k = d_model // h                       # 512 / 8 = 64
        self.h = h
        self.linears = clones(nn.Linear(d_model, d_model), 4)   # W_Q, W_K, W_V, W_O

    def forward(self, query, key, value, mask=None):
        nbatches = query.size(0)
        query, key, value = [
            lin(x).view(nbatches, -1, self.h, self.d_k).transpose(1, 2)   # (b, seq, 512) -> (b, 8, seq, 64)
            for lin, x in zip(self.linears, (query, key, value))
        ]
        x, self.attn = attention(query, key, value, mask=mask, dropout=self.dropout)
        x = x.transpose(1, 2).contiguous().view(nbatches, -1, self.h * self.d_k)   # concat heads back to 512
        return self.linears[-1](x)   # W_O: final output projection
Why bother splitting?

A single 512-dimensional attention pass produces one weighted average per word — which necessarily blends together every relationship that word has with its neighbors into one blurry summary. Eight smaller, independent attention computations let each head specialize — one might learn syntax, another positional proximity, another semantic similarity — and the final linear layer learns how to combine those eight specialized views.

1.8Feed-Forward, Embeddings & Position

Where each word thinks alone, and how order gets in

After attention lets positions exchange information, the feed-forward network processes each position independently and identically — the exact same two weight matrices apply to every word in the sequence.

Cell 17 — PositionwiseFeedForward
class PositionwiseFeedForward(nn.Module):
    def __init__(self, d_model, d_ff, dropout=0.1):
        self.w_1 = nn.Linear(d_model, d_ff)   # 512 -> 2048, expand
        self.w_2 = nn.Linear(d_ff, d_model)   # 2048 -> 512, compress back

    def forward(self, x):
        return self.w_2(self.dropout(self.w_1(x).relu()))
Math FFN(x) = W₂ · ReLU(W₁x + b₁) + b₂

d_ff = 2048 is 4× d_model. The expand-then-compress bottleneck forces the model to learn a compressed, useful intermediate representation; the ReLU is what stops the two linear layers from collapsing into a single linear transform.

Embeddings & positional encoding

Cell 18 — Embeddings
def forward(self, x):
    return self.lut(x) * math.sqrt(self.d_model)   # scale by √512 ≈ 22.6

The scaling matters because positional encodings (below) are bounded between −1 and 1. Left unscaled, a freshly-initialized embedding could be numerically tiny next to the positional signal, letting position drown out word identity.

Cell 19 — PositionalEncoding
pe[:, 0::2] = torch.sin(position * div_term)   # even dimensions: sine
pe[:, 1::2] = torch.cos(position * div_term)   # odd dimensions: cosine
self.register_buffer('pe', pe)                  # fixed — not a trainable parameter
Math PE(pos, 2i) = sin(pos / 10000^(2i/d))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
Analogy

Each of the 256 sine/cosine pairs spins at its own frequency — from fast (dimension 0) to extremely slow (dimension 511), like a clock's second hand and hour hand moving at different speeds. No single "hand" tells you the position on its own, but read all 512 dimensions together at once, and the combination is unique to that position — exactly like reading a clock face.

register_buffer() is the detail worth not skimming past: it stores the PE table with the model's state dict so it saves and loads correctly, but never computes a gradient for it. Positional encoding is fixed, not learned.

1.9Assembling the Full Model

make_model() — one function, every piece wired together

Cell 21 — make_model()
def make_model(src_vocab, tgt_vocab, N=6, d_model=512, d_ff=2048, h=8, dropout=0.1):
    c = copy.deepcopy
    attn = MultiHeadedAttention(h, d_model)
    ff = PositionwiseFeedForward(d_model, d_ff, dropout)
    position = PositionalEncoding(d_model, dropout)
    model = EncoderDecoder(
        Encoder(EncoderLayer(d_model, c(attn), c(ff), dropout), N),
        Decoder(DecoderLayer(d_model, c(attn), c(attn), c(ff), dropout), N),
        nn.Sequential(Embeddings(d_model, src_vocab), c(position)),
        nn.Sequential(Embeddings(d_model, tgt_vocab), c(position)),
        Generator(d_model, tgt_vocab),
    )
    for p in model.parameters():
        if p.dim() > 1:
            nn.init.xavier_uniform_(p)   # stable random starting weights
    return model

attn and ff are each built once, then deep-copied fresh every time they're reused — once for the encoder's self-attention, twice for the decoder (self-attention and cross-attention). Each copy trains completely independently, for the same reason clones() matters in 1.3.

Key insight

Xavier initialization draws weights from U(−√(6/(fan_in+fan_out)), √(6/(fan_in+fan_out))), keeping activation and gradient variance roughly constant across layers. Skip it, and a 6-layer stack would struggle to converge at all — deep networks are unusually sensitive to how they start.

Model Training

A freshly built model from Part 1 knows nothing. This part covers exactly how training data is shaped, what happens on every optimizer step, and the two regularization techniques — warmup scheduling and label smoothing — that make Transformer training stable.

2.1Batches & Masking

The Batch object — where teacher forcing actually happens

Cell 23 — Batch
class Batch:
    def __init__(self, src, tgt=None, pad=2):
        self.src = src
        self.src_mask = (src != pad).unsqueeze(-2)   # True wherever src is a real token
        if tgt is not None:
            self.tgt = tgt[:, :-1]        # decoder INPUT: drop the last token
            self.tgt_y = tgt[:, 1:]       # labels: drop the first token
            self.tgt_mask = self.make_std_mask(self.tgt, pad)

The target sequence is split into two shifted views of itself. At decoder input position i, the model has seen tokens 0..i-1 and must predict token i — that one-position shift is the entire mechanism behind teacher-forced, autoregressive training. make_std_mask then combines the causal mask from 1.6 with the padding mask into the single tgt_mask the decoder actually uses.

Analogy

Like a fill-in-the-blank worksheet: the decoder sees words 1 through n−1 and has to guess words 2 through n. tgt_y is the answer key used to grade every guess; the mask is the ruler laid over the page so nothing can peek ahead at the next blank.

2.2Optimizer & Learning Rate Schedule

rate() — warm up, then decay

Rather than a fixed learning rate, the Transformer ramps up linearly for the first warmup steps, then decays proportional to the inverse square root of the step count.

Cell 26 — rate()
def rate(step, model_size, factor, warmup):
    if step == 0:
        step = 1
    return factor * (
        model_size ** (-0.5) * min(step ** (-0.5), step * warmup ** (-1.5))
    )
Math lr = factor · d_model⁻⁰·⁵ · min(step⁻⁰·⁵, step · warmup⁻¹·⁵)
Why warm up at all?

Early in training, weights are freshly randomized and gradient estimates are noisy — a large learning rate at step one can push the model somewhere it never recovers from. A short, low-LR ramp lets internal statistics (especially inside LayerNorm) settle before the rate climbs to its productive peak. Constant low rates, by contrast, would just be too slow to be practical.

2.3Label Smoothing

Softening the target so the model never gets overconfident

Instead of a hard target (100% on the correct token, 0% everywhere else), label smoothing spreads a small amount of probability mass across every other token in the vocabulary.

Cell 28 — LabelSmoothing
class LabelSmoothing(nn.Module):
    def __init__(self, size, padding_idx, smoothing=0.0):
        self.criterion = nn.KLDivLoss(reduction='sum')
        self.confidence = 1.0 - smoothing         # e.g. 0.9 on the correct token
        self.smoothing = smoothing                # e.g. 0.1 spread across the rest

    def forward(self, x, target):
        true_dist = x.data.clone()
        true_dist.fill_(self.smoothing / (self.size - 2))
        true_dist.scatter_(1, target.unsqueeze(1), self.confidence)
        true_dist[:, self.padding_idx] = 0
        return self.criterion(x, true_dist.detach())
with smoothing = 0.1probability mass
correct token0.90
every other real token0.10 / (V − 2), each
padding token0 — zeroed explicitly
Why deliberately make the target fuzzier?

A model trained against a perfectly confident (one-hot) target is pushed to make its own predictions as extreme as possible — which tends toward overconfidence and worse generalization. Capping the target at 90% measurably hurts perplexity, but the tradeoff pays off in BLEU score and real translation quality, because the model never learns to assign near-zero probability to plausible alternatives.

Why gradient accumulation?

accum_iter=10 simulates a larger effective batch (320 per GPU) without needing more GPU memory. The Transformer's training dynamics are notably sensitive to batch size — too small, and gradients get noisy enough to hurt convergence.

3.3Greedy Decoding

greedy_decode() — encode once, decode many

Cell 33 — greedy_decode()
def greedy_decode(model, src, src_mask, max_len, start_symbol):
    memory = model.encode(src, src_mask)                    # encode the source ONCE
    ys = torch.zeros(1, 1).fill_(start_symbol)
    for i in range(max_len - 1):                             # decode ONE token per iteration
        out = model.decode(memory, src_mask, ys, subsequent_mask(ys.size(1)))
        prob = model.generator(out[:, -1])
        _, next_word = torch.max(prob, dim=1)                # greedy: take the highest-probability token
        ys = torch.cat([ys, next_word.unsqueeze(0)], dim=1)
    return ys

This is the encode-once-decode-many pattern from 1.1, made concrete: model.encode() runs a single time, but model.decode() runs up to max_len times, re-using the same memory at every step while the growing sequence ys and its expanding causal mask are the only things that change.

3.4Attention Visualization

Reading the .attn attribute out of a trained model

Once trained, each MultiHeadedAttention module has already stored its own attention weight matrix from the last forward pass — attention(), remember, returns both the output and the weights (1.7).

Cells 46–50 — reaching into a trained model
encoder_attn  = model.encoder.layers[layer].self_attn.attn     # source looking at source
decoder_self  = model.decoder.layers[layer].self_attn.attn     # target looking at earlier target
decoder_cross = model.decoder.layers[layer].src_attn.attn      # target looking at source (memory)

Three distinct views come out of this: encoder self-attention (how source tokens relate to each other), decoder self-attention (causal — target tokens looking at earlier target tokens), and decoder-encoder cross-attention, which shows the word-to-word alignment between the two languages.

Analogy

Like an X-ray of the model's reading habits — for any word the decoder writes, you can see exactly which source word it was leaning on most heavily at that moment.
